# 自動版號標記（SemVer Tagging）

本技能旨在為 main（或 master）分支的合併節點打上版本號 Tag。

## 什麼時候觸發此技能？

1. 當使用者輸入 `/agy-git-flow:tag`。
2. 當使用者要求「打 tag」、「自動判斷版號」時。

## 執行的實作步驟

### 步驟 0：工作區狀態檢查（防越界機制）

1. 執行 `git status --porcelain` 檢查工作區是否乾淨。
2. 若偵測到有未暫存、已暫存或未追蹤的檔案（工作區非乾淨狀態）：
   - **必須立即中止流程**，嚴格禁止在本技能內自行拼湊或執行原生 `git add` 或 `git commit` 指令，亦嚴格禁止詢問使用者是否代為提交。
   - 明確提示使用者：「偵測到工作區尚有未提交的變更。打標籤前工作區必須保持乾淨，避免拉取最新節點時發生衝突。請先使用 `/agy-git-flow:commit` 完成正規提交流程後再進行標記。」

### 步驟 1：防呆機制與標籤同步

1. 若專案設定有遠端儲存庫，先執行 `git fetch --all --tags --prune` 確保取得所有標籤與提交歷史。
2. 執行 `git branch --show-current` 檢查當前分支。
3. 若當前分支不是 main 或 master：
   - **必須立即中止流程**，並告知使用者：「標記版本號必須在 main 主分支上執行，請先切換至 main 分支。」
   - **嚴格防越界規範**：嚴格禁止在此處詢問使用者是否代為切換分支或代為提交。
4. 若主分支落後遠端，先執行 `git pull --ff-only` 確保為最新狀態。

### 步驟 2：檢查手動指定版號

1. 若使用者明確提供版號（例如 `/agy-git-flow:tag v1.2.3`）。
2. 直接跳過後續分析，使用指令 `git tag <手動版號>` 打上標籤，提示推播後結束流程。

### 步驟 3：找出未標籤的合併節點

1. 使用 `git log --merges main` 找出所有合併節點。
2. 比對現有 Tag，過濾出尚未被打上 Tag 的節點。

### 步驟 4：處理多個未標籤節點（ask_question）

1. 若只有一個節點，直接進入第五步。
2. 若有多個節點，使用 `ask_question` 工具確認範圍：
   ```json
   {
     "questions": [
       {
         "question": "發現多個未標籤的合併節點，請問要標籤哪種範圍？",
         "options": ["(Recommended) 僅把最近的一次合併節點打上版本號", "全部的合併節點都要打上標籤"],
         "is_multi_select": false
       }
     ],
     "toolSummary": "確認標籤範圍",
     "toolAction": "詢問要標籤幾個合併節點"
   }
   ```

### 步驟 5：版號判斷（SemVer 2.0.0）

針對每個確定要打 Tag 的合併節點：
1. 分析該合併節點的變更歷史。
2. 依據 SemVer 2.0.0 進行判斷：
   - MAJOR（X.y.z）：破壞性變更時遞增。
   - MINOR（x.Y.z）：向下相容新功能時遞增。
   - PATCH（x.y.Z）：向下相容錯誤修復時遞增。
3. 與前一個 Tag 加算，最終版號必須加上 `v` 前綴（例如 `v1.3.0`）。

### 步驟 6：執行標記與說明

1. 執行 `git tag <版號> <合併節點的 hash>`。
2. 總結標記結果，並從技能列表中讀取執行 `agy-git-flow:push`（或 `push`）技能推播標籤至遠端。

## 嚴格禁止事項（Anti-patterns）

1. **嚴格禁止執行原生 `git commit` 指令**：本技能完全不包含提交程式碼的功能。
2. **嚴格禁止跨技能越界代理提交**：當工作區不乾淨或處於非主分支時，必須直接中斷並向使用者明確說明，嚴格禁止自行詢問代為提交或私自執行 git 提交指令。
