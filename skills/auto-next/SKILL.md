# `auto-next` 技能指令

## 目標 (Goal)
當使用者輸入 `/antigravity-git-flow:auto-next`，或是表達「我接下來要做什麼」、「自動幫我推進」時，請扮演「隱形的版本控制管家」，自動分析當前工作區狀態並執行最合適的 Git Flow 操作。這是一個專為完全不懂 Git 的小白設計的「自動」指令。

## 執行流程 (Execution Flow)

請依序（優先度由高到低）檢查以下狀態，只要符合條件，就**直接執行**對應的行動。請務必在背景安靜地使用指令（如 `git status`, `git log` 等）檢查，不要將生硬的指令輸出給使用者看，只需用白話文解釋你即將執行的動作。

### 階段零：遠端狀態更新 (Remote Fetch)
0. **條件**：若當前專案為 Git 儲存庫且設定有遠端儲存庫（`git remote` 有輸出）。
   **行動**：在背景安靜執行 `git fetch --all --prune --tags`，確保本地取得遠端最新的分支進度與標籤（Tags）資訊，以利後續做出最準確的狀態判斷。

### 階段一：基礎建設 (Infrastructure)
1. **條件**：執行 `git status` 失敗（代表沒有 `.git` 目錄），或是缺少 `main` 或 `develop` 分支。
   **行動**：請告訴使用者「目前專案似乎還沒設定好版本控制」，然後請從您的 `<skills>` 列表中尋找 `init` 技能，讀取並執行其邏輯。

### 階段二：保護工作進度 (Save Progress)
2. **條件**：執行工作區檢查，發現有修改 (M)、新增 (A/?) 或刪除 (D) 的檔案。
   **行動**：請告訴使用者「發現您有寫好的新程式碼，我先幫您把進度存起來喔！」，然後請從您的 `<skills>` 列表中尋找 `commit` 技能，讀取並執行其邏輯。

### 階段三：同步與協作 (Sync)
3. **條件**：工作區乾淨，但執行 `git status` 發現本地分支落後遠端 (behind remote)。
   **行動**：請告訴使用者「發現雲端有團隊的新進度，先幫您同步更新下來喔！」，並執行 `git pull`（或 `git pull --rebase`）拉取最新變更。
4. **條件**：工作區乾淨，但執行 `git status` 發現本地分支進度超前遠端 (ahead of remote)，或是遠端根本沒有這個分支。
   **行動**：請告訴使用者「您的程式碼已經存好了，現在幫您備份到雲端！」，然後從您的 `<skills>` 列表中尋找 `push` 技能並執行。

### 階段四：流程推進 (Flow Progression)
5. **條件**：目前在 `feature/*` 分支上，工作區乾淨且已同步。
   **行動**：這代表新功能開發完了，請告訴使用者即將進行合併，並請從您的 `<skills>` 列表中讀取並執行 `merge` 技能。
6. **條件**：目前在 `release/*` 或 `hotfix/*` 分支上，且工作區乾淨已同步。
   **行動**：這代表發布前的測試/修復已完成，請告訴使用者即將進行合併與發布確認，並請從您的 `<skills>` 列表中讀取並執行 `merge` 技能。
7. **條件**：目前在 `main` 或是 `master` 分支上，且有最新的合併紀錄尚未打標籤 (Tag)。
   **行動**：這代表剛發布了新版本，請讀取並執行 `tag` 技能，接著可建議執行 `github-release`。

### 階段五：迷航求助 (Fallback)
8. **條件**：目前狀態非常健康（例如在 `develop` 且一切同步），沒有明顯的下一步。
   **行動**：使用 `ask_question` 工具顯示互動選單，詢問使用者想做什麼（判斷使用者選擇時，請依據語意進行對應，不必死磕 Emoji）：
   - 標題：「目前的專案狀態很健康，都已經妥善儲存囉！接下來您想做什麼呢？」
   - 選項（請帶入 Emoji）：
     - *(Recommended)* 🆕 我要開發新功能 (建立 feature 分支)
     - 📦 我要準備發布新版本 (release)
     - 🐛 我要修復緊急 Bug (建立 hotfix 分支)
     - 🔄 我要從雲端更新程式碼 (git pull)

## 溝通準則 (Communication Guidelines)
- **安心感**：在執行任何動作前，用一句話報備，讓使用者知道 AI 正在幫他做對的事。
