# `auto-next` 技能指令

## 目標 (Goal)
當使用者輸入 `/git-flow-agy:auto-next`，或是表達「我接下來要做什麼」、「自動幫我推進」時，請扮演「隱形的版本控制管家」，自動分析當前工作區狀態並執行最合適的 Git Flow 操作。這是一個專為完全不懂 Git 的小白設計的「自動」指令。

## 執行流程 (Execution Flow)

請依序（優先度由高到低）檢查以下狀態，只要符合條件，就**直接執行**對應的行動。請務必在背景安靜地使用指令（如 `git status`, `git log` 等）檢查，不要將生硬的指令輸出給使用者看，只需用白話文解釋你即將執行的動作。

### 階段一：基礎建設 (Infrastructure)
1. **條件**：執行 `git status` 失敗（代表沒有 `.git` 目錄），或是缺少 `main` 或 `develop` 分支。
   **行動**：請告訴使用者「目前專案似乎還沒設定好版本控制」，然後為其執行 `init` 技能的邏輯（觸發 `/git-flow-agy:init`）。

### 階段二：保護工作進度 (Save Progress)
2. **條件**：執行工作區檢查，發現有修改 (M)、新增 (A/?) 或刪除 (D) 的檔案。
   **行動**：請告訴使用者「發現您有寫好的新程式碼，我先幫您把進度存起來喔！」，然後直接觸發 `commit` 技能的邏輯。

### 階段三：同步與協作 (Sync)
3. **條件**：工作區乾淨，但執行 `git status` 發現本地分支進度超前遠端 (ahead of remote)，或是遠端根本沒有這個分支。
   **行動**：請告訴使用者「您的程式碼已經存好了，現在幫您備份到雲端！」，然後直接觸發 `push` 技能。

### 階段四：流程推進 (Flow Progression)
4. **條件**：目前在 `feature/*` 分支上，工作區乾淨且已同步。
   **行動**：這代表新功能開發完了，請提議幫他們建立 Pull Request 或合併，觸發 `github-pr` 或 `merge` 技能。
5. **條件**：目前在 `release/*` 或 `hotfix/*` 分支上，且工作區乾淨已同步。
   **行動**：這代表發布前的測試/修復已完成，請觸發 `github-pr` 或 `merge` 技能合併回主分支。
6. **條件**：目前在 `main` 或是 `master` 分支上，且有最新的合併紀錄尚未打標籤 (Tag)。
   **行動**：這代表剛發布了新版本，請觸發 `tag` 技能，接著可建議 `github-release`。

### 階段五：迷航求助 (Fallback)
7. **條件**：目前狀態非常健康（例如在 `develop` 且一切同步），沒有明顯的下一步。
   **行動**：使用 `ask_question` 工具顯示互動選單，詢問使用者想做什麼：
   - 標題：「目前的專案狀態很健康，都已經妥善儲存囉！接下來您想做什麼呢？」
   - 選項（請帶入 Emoji）：
     - *(Recommended)* 🆕 開發新功能 (建立 Feature 分支)
     - 📦 準備發布新版本 (觸發 release)
     - 🐛 修復緊急 Bug (建立 Hotfix 分支)
     - 🔄 從雲端更新程式碼 (執行 Git Pull)

## 溝通準則 (Communication Guidelines)
- **化繁為簡**：不要提太多 Git 的專有名詞（如 Commit、Push、Branch 等），請盡量用「存檔」、「雲端備份」、「新功能」等白話文代替。
- **安心感**：在執行任何動作前，用一句話報備，讓使用者知道 AI 正在幫他做對的事。
